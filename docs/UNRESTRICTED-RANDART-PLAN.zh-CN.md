# 混沌神器与近战溢出增伤实现说明

更新日期：2026-10-26。已按以下规则实现；客户端版本为 `4.9.6.0.0.3`，物品存档格式升级为 `4.9.27`，可读取旧存档。以下保留已确认规则和实施方案，便于核对。

## 已确认规则

### 新类型与词条

- 增加一种比普通随机神器（RA）更稀有的新类型：混沌神器（Chaos Artifact，简称 CA）。
- 新类型的功能性词条不受装备部位限制，正负词条进入同一个候选池，每个候选词条等概率。
- 保留底材固有词条，再新增 1～30 条；每个新增条数等概率，均为 1/30。
- 新增词条互不重复；底材已有词条从新增候选池中排除。最终总数可以超过 30 条。
- 命中、伤害和护甲加值单独生成，不占用新增功能性词条的数量。
- 不同词条即使效果重叠或互相覆盖，也全部保留，各占一条，不因此删除或补抽。例如火焰免疫与火焰抗性、全感知与邪恶感知均可共存；实际效果按游戏原有规则结算。
- 取消新类型原有 RA 的强度预算、部位数值上限和用于平衡强度的组合限制；不因强词条增加而补偿负面词条。
- 不随机生成仅用于存档、显示或物品生成控制的内部标记；实际候选池见 `src/server/randart.c` 的 `chaos_artifact_make`。

### 主动激活能力

- 新增随机词条仅包含常驻属性与负面词条，不抽取新的主动激活能力。
- 保留底材原有的主动能力，按原有条件、效果、成功率和冷却规则使用。
- 没有主动能力的底材不会仅因成为新类型而获得主动激活能力；激活标记不作为独立新增候选词条。
- 原有资格限制仍有效：Mage Staff 吸收器械属于会改造底材的融合操作，神器仍不能进行该操作；龙鳞甲吐息、元素戒指等原有可保留激活不变。

### 名称与外观

- 使用 Chaos Artifact 名称和 [CA] 前缀，具体物品仍具有随机神器名称。
- 名称与地面物品标识使用青色闪烁，保留底材原有的图形和形状。
- 沿用现有鉴定与可见性规则；客户端关闭闪烁时使用固定青色。
- 与现有真神器的金色、普通 RA 的紫色分别显示。

### 共用数值

- 每件装备只抽取一个共用 PVAL，所有依赖 PVAL 的原有词条和新增词条均使用它。
- 抽取范围为 -10～+20，包含 0；31 个整数等概率，每个为 1/31。
- 底材固有词条保留，但原 PVAL 数值统一重抽。例如原本 +5 速度的戒指抽到 -3 后，速度变为 -3。
- 抽到 0 时保持 0，依赖 PVAL 的数值加成为零；非 PVAL 词条按各自机制生效。
- PVAL 的概率与词条抽取权重分别计算，不先单独决定正负。

### 命中、伤害和护甲加值

- 命中加值、伤害加值、护甲加值均从 -10～+50 的 61 个整数中等概率抽取，包含 0。
- 三项各自独立抽取，互不要求相等，也不使用共用 PVAL。
- 新类型不再套用普通 RA 对武器、法师杖、手套等部位的生成加值上限。
- 此处的护甲加值是装备的额外护甲修正，与底材基础护甲分别结算。

### 底材物理数值

- 保留底材的武器伤害骰、基础护甲和重量，不通过新类型生成器重抽或修改。
- 装备类型、子类型和穿戴部位沿用底材。
- 例如底材为 2d6，新类型仍为 2d6；伤害加值另按 -10～+50 独立抽取。

### 生成概率与来源

- 每次原本要生成一件新 RA 时，10% 生成新类型，90% 生成普通 RA。
- 所有原本可生成 RA 的正常来源均采用该比例，包括掉落、地面、宝箱和神器制造卷轴等制造途径。
- 该比例用于 RA 类型分配，不额外增加一次 RA 掉落机会。
- 已有 RA 的类型固定，升级、登录、读档或重新读取属性时，不重新判定这 10%。
- 具体实现需核对所有创建与重新生成属性的入口，避免重试或属性重建反复抽取类型。

### 普通 RA 的配套调整

- 取消“装备过强就强制附加 aggravation”的补偿规则。
- 底材自带或随机诅咒产生的 aggravation 仍保留。
- 已有普通 RA 一并处理：按旧种子和旧生成过程重建原有属性，只移除明确来自强度补偿的 aggravation；其他词条、数值、等级、名称及铭文保持。
- 旧 RA 当初因该规则被删除的潜行、隐身不追溯补回，不重洗旧装备。
- 以后生成的普通 RA 完整取消该补偿规则及其连带删除潜行、隐身的逻辑；其余普通 RA 生成规则沿用现状。
- 区分旧普通 RA、新普通 RA 和 CA 的生成方式，保持旧种子解释稳定；旧 RA 不会在升级或读档时变成 CA。

### 普通玩家的近战次数溢出转换

- 适用对象是作为攻击方的普通玩家，攻击怪物和其他玩家时均可获得加成；怪物作为攻击方不获得此加成。
- 普通玩家原本计算得到的近战次数为 N：N 不超过 20 时沿用现有行为。
- N 超过 20 时，实际攻击次数仍为 20，直接近战伤害增加 (N - 20) / 20，即每击倍率为 N / 20。
- 示例：21 次为 +5%，25 次为 +25%，30 次为 +50%，40 次为 +100%。
- 所有来源的近战次数均参与计算，包括技能、装备和临时效果；加成线性增长。
- 管理员原有超过 20 次攻击的行为保持，不同时获得溢出换算。
- 武器、双持和徒手的直接近战伤害纳入该规则，法术、射击及独立触发效果沿用现有机制。
- 不通过换算增加实际攻击或逐次触发的机会；折算在暴击、背刺与 vorpal 后、目标防御及 PvP 减伤前应用，人物面板显示实际次数和增伤比例。

## 实施方案

物品保存 `randart_version`，区分旧 RA、新普通 RA 和 CA；近战原始次数 `melee_blows` 每次能力重算时更新，不占永久存档。

### 1. 固定生成类型并保存

- 在物品记录中保存显式的生成类型/版本标记，区分旧普通 RA、新普通 RA 和 CA，不占用已有随机种子的位。
- 旧档读取时使用旧普通 RA 标记，保留原完整种子。新增标记需要更新存档格式并保留旧档读取能力。
- 只在新 RA 首次创建时进行 10% 判定。生成失败重试、属性查询、重启、重铸和诅咒反转均不重新抽取类别；既有行为确实重抽种子时，保留物品类别。
- 逐项核对 `object2.c` 的自然生成、`spells2.c` 的制造与其他创建入口，避免遗漏特殊来源。
- 物品仍属于随机神器，沿用普通 RA 的存储、交易、符文及模式规则，不进入真神器唯一性计数或真神器收藏页。

### 2. 生成 CA 属性

- 从底材复制固有词条和物理数值，保留原主动能力及原有神器基础保护。
- 抽取新增条数，在排除已有词条后，从等权候选池中无放回抽取；随后独立抽取共用 PVAL 及三个攻防加值。
- CA 使用独立生成分支，不执行普通 RA 的能力评分回退、数值裁剪、冗余词条删除或强词条补偿。
- CA 的生成不因抽到某项强属性而重新选择种子或词条，以免破坏已确定的等概率规则。原有 RA 场景准入与底材合法性规则保留。
- 审查装备计算中只对特定槽位读取的词条，确保跨部位出现的常驻效果能进入对应结算；同时遵循已确认的效果覆盖规则。
- 区分物品附带的负面词条和单纯的负 PVAL，不因 PVAL 为负而额外强制增加诅咒词条。诅咒所需的原生状态按正常装备机制保存与处理。

候选词条清单按以下类别核对，每个具体词条单独等权。只采用已有实现的常驻效果，不为未实现的占位标记增加新玩法。

| 类别 | 纳入核对的功能性词条 |
| --- | --- |
| 数值属性 | 六维、速度、额外近战次数、生命、法力、潜行、搜索、红外视力、挖掘、幸运、拆陷阱、暴击 |
| 属性维持 | 力量、智力、智慧、敏捷、体质、魅力的维持，分别作为候选 |
| 抗性 | 各元素及恐惧、明暗、失明、混乱、声音、碎片、地狱、空间、混沌、祛魔、时间、魔力、传送等已有抗性 |
| 免疫 | 酸、电、火、寒、毒、水、地狱等已有免疫；与对应抗性分开抽取 |
| 感知 | 感知隐形、各类 ESP、全感知、自动鉴定等已有常驻能力 |
| 生存与移动 | 自由行动、生命维持、生命/法力恢复、缓慢消化、羽落、飞行、攀爬、行水、幽灵形态等已有能力 |
| 战斗 | 各类 slay、kill、元素品牌、吸血、混沌、vorpal、地震、额外射击、额外射程/威力等已有常驻效果 |
| 光与光环 | 火、电、寒光环，已有发光与光色属性 |
| 其他常驻效果 | 祝福、各档抗魔、隐形、反射，以及已有的装备自身抗破坏/抗强化等功能性属性 |
| 负面效果 | aggravation、经验/生命/法力流失、随机传送、禁传送、禁魔、禁止近战、自动诅咒、普通/重/永久诅咒、古老诅咒、黑息、复制诅咒、禁止丢弃等已有负面效果 |

- 相同词条不会重复；效果重叠的不同词条可以共存。候选排除和计数以最终明确的功能性词条清单为准。
- 内部生成标记、任务/活动控制、鉴定显示格式、未实现的占位属性及新的主动能力不进入随机池；双手使用要求等底材结构信息继承原物品。
- 弹药等特殊底材对 PVAL 的原有用途需要单独核对，防止共用数值被错误解释为爆炸元素等其他信息。

### 3. 兼容旧普通 RA

- 保留旧生成过程与随机数调用次序，在原属性完整重建后按来源精准移除强制 aggravation。
- 如果底材本身具有 aggravation，或者来自原有随机诅咒，即使最终标记相同也必须保留。
- 旧 RA 的能力评分、价格及使用等级等重建结果保持原计算结果，不因去掉一个标记而重算整件装备。
- 通过旧种子参考结果对比，覆盖玩家背包、装备、住宅、Vault 和地面物品；不需要逐件手工编辑存档。

### 4. 近战溢出折算

- 在 `xtra1.c` 的近战能力计算中保留合法状态下的原始次数 N，再对普通玩家将实际次数限制为 20。禁用近战、幽灵及其他原有状态限制继续有效。
- 溢出量为运行时派生值，每次能力重算时重新计算，换装、临时效果消失后立即更新，不写入永久存档。
- 在 `cmd1.c` 的玩家攻击怪物和玩家攻击玩家路径中统一折算，建议位于暴击、背刺、vorpal 等直接伤害计算之后、目标防御与 PvP 减伤等正常结算之前。
- 使用宽整数计算每击伤害乘 N/20，最终按整数伤害取整；不忽略目标防御或原有战斗限制。
- 适用于使用该近战次数机制的武器、双持和徒手直接打击。射击、法术、独立技能及额外触发效果保持原机制；吸血按原有实际伤害与恢复上限结算，不额外再乘一次。
- 审查范围攻击与其他特殊近战调用，防止遗漏主打击或把独立触发伤害重复放大。
- 面板显示实际攻击次数和溢出增伤，例如“20 次，近战伤害 +25%”；伤害预估与实际结算一致，避免先按 N 次计算总伤害后再次乘倍率。
- 不把原始 N 直接塞进旧的有限位宽攻击次数数据。管理员保留原有行为并跳过折算，怪物攻击路径不改。

### 5. 显示、既有玩法与交付

- 扩展现有神器前缀、动态颜色与地面显示逻辑；同步处理自动拾取、自动铭文、匹配及导出，保留既有鉴定规则。
- 新客户端显示青色闪烁和溢出增伤；关闭闪烁显示固定青色。沿用现有旧客户端静态颜色兼容方式。
- CA 的价格和使用等级默认沿用现有 RA 计算与配置。针对更高属性使用宽整数和合法存储范围，避免溢出或截断；价格与等级计算不反向裁剪或重抽 CA 词条。
- 继续遵循既有诅咒反转资格、符文使用、模式、交易和持有规则，核对这些路径不会丢失 CA 类别或改变已固定的属性解释。
- 构建 Windows 64 位服务端和客户端，按此前约定提供替换文件压缩包，附停服、备份、存档升级与替换说明。

## 验证范围

- 保存、重启、迁移、重新鉴定后，新类型和属性保持一致；旧普通 RA 的兼容结果可核对。
- 新增词条数量、抽取权重、PVAL 和各来源的类型概率符合上述规则。
- 重叠词条分别计数并保留，属性重建时不被普通 RA 的清理逻辑删除或补抽。
- 有主动能力的底材在新类型上保留原有使用行为；其他底材不新增主动激活能力。
- [CA] 名称和青色闪烁在物品列表与地面正确显示，关闭闪烁时固定为青色，原有自动拾取及铭文匹配继续可用。
- 命中、伤害和护甲加值均可独立达到 -10、0、+50，不被普通 RA 的部位加值规则裁剪。
- 生成及属性重建后，伤害骰、基础护甲、重量和装备部位与底材一致。
- 跨部位词条实际生效；负数与零 PVAL 不被原生成器自动修正或裁剪。
- 近战 19、20、21、25、40 次及临时加成消失后的伤害正确，管理员不重复换算。
- 玩家攻击怪物和其他玩家均可获得近战溢出增伤，怪物攻击不获得该加成；射击、法术与独立触发效果保持原有行为。
- 实际伤害、战斗消息和面板一致；实际攻击数及触发次数仍按现有上限处理。
- 普通 RA 不再因强度强制附加 aggravation，原有随机诅咒及底材负面效果按来源保留。
