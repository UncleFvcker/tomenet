# Windows 64 位部署、连接和迁移

这两个安装包来自 `UncleFvcker/tomenet` 的 `merge/everlasting-skill` 分支，
保留基于 `1iuh/master` 的自定义功能，包含 Everlasting 免费回城复活、Skill 药水和免费洗点。
具体源码提交、架构和随包 DLL 记录在安装包内的 `BUILD-INFO.json`。

## 1. 新机器部署服务端

1. 将服务端 ZIP **完整解压**到可写目录，例如 `D:\Games\TomeNET-Server`。
   不要只复制 EXE，也不要直接在 ZIP 内运行。无需安装 GCC、MSYS2 或 SDL。
2. 编辑 `lib\config\tomenet.cfg`。默认游戏端口是 TCP `18348`；
   `REPORT_TO_METASERVER = false`，不会自动发布到公共服务器列表。
   打包时会为 `CONSOLE_PASSWORD` 生成随机密码；需要修改时，请使用 ASCII 字母和数字。
   管理控制台端口默认 `18349`，安全停服脚本只从本机连接该端口。
3. 双击 `start-server.bat`，保持该窗口和机器运行。第一次启动会生成世界和存档，
   请等待启动完成。日志位于 `lib\data\tomenet.log`。
4. 先使用同一台机器上的客户端连接 `127.0.0.1:18348`。
   验证成功后，再开放其他机器的访问。

局域网访问时，服务端机器在管理员 PowerShell 中运行下列命令，将路径替换成实际路径：

```powershell
New-NetFirewallRule -DisplayName 'TomeNET game TCP 18348' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 18348 -Program 'D:\Games\TomeNET-Server\tomenet.server.exe' -Profile Any
```

运行 `ipconfig` 查看服务端的 IPv4 地址，例如 `192.168.1.20`；其他机器的客户端连接这个地址。
防火墙弹窗不要选择给 EXE 开放所有端口，使用上面的游戏端口规则即可。
互联网访问还需要在路由器做 TCP `18348` 的端口转发；云机器则在安全组开放 TCP `18348`。
不要对外开放管理端口 `18349` 或网关端口 `18400`。
家庭网络如果处于运营商 NAT 后面，单独做端口转发无法提供公网入口。

这套启动方式适合手动开服：重启 Windows 后需要再次双击启动，休眠和关机都会中断服务。

## 2. 打开客户端

1. 将客户端 ZIP 完整解压，例如 `D:\Games\TomeNET-Client`。
2. 双击 `start-client.bat`，输入服务端 IP 或域名和游戏端口。
   同机测试直接按两次 Enter，使用默认的 `127.0.0.1`、`18348`。
3. 在游戏窗口中输入账号名和密码。首次使用新的账号名会创建账号，
   再按界面创建角色。首次启动若出现音频提示或显示设置问题，按提示确认即可。
   选择 **Everlasting** 模式才能使用本次调整的死亡规则。
4. 后续仍使用该账号名、密码登录。客户端不保存世界存档；世界、账号和角色均在服务端。

也可以创建快捷方式或在客户端目录中执行：

```powershell
.\TomeNET.exe -p18348 192.168.1.20
```

直接双击 `TomeNET.exe` 会进入原项目的服务器选择流程，因此连接自己的服务器时推荐使用启动脚本。
DLL 已包含在安装包中；不要从其他网站随意替换 DLL，也不要混用 32 位和 64 位文件。
客户端支持 SDL 音频，仓库附带的音效和音乐资源有限，并非完整官方音频包。

## 3. 停服和备份

双击服务端目录中的 `stop-server.bat`。它读取当前配置，通过本机管理端口要求服务端
保存在线角色、世界、任务和封禁列表，并等待进程退出。看到
`Server exited after saving` 才表示可以开始备份。

若停服脚本报错，请检查配置中的控制台密码、端口以及服务端日志。
脚本按当前目录中 EXE 的实际路径识别进程，不依赖可能过期的 `lib\data\tomenet.pid`。
也可以登录管理员角色，在游戏聊天中执行 `/shutdown 0`，保存所有在线角色和世界后退出。
当前 Windows 构建没有启用窗口关闭保存处理器，直接点服务端窗口的 X 不能保证保存。
不要使用任务管理器强制结束进程后马上复制正在写入的存档。

**最简单完整的备份是：停服后压缩整个服务端目录。** 例如：

```powershell
Compress-Archive -LiteralPath 'D:\Games\TomeNET-Server' -DestinationPath 'E:\Backups\TomeNET-Server-backup.zip'
```

备份目录需要事先创建；已有同名 ZIP 时请换一个名称。备份包含账号及管理凭据，应保存在可信位置。
若希望保留包括隐藏文件在内的全部文件，也可以直接复制整个服务端目录到备份盘。

关键数据包括：

| 路径 | 内容 |
| --- | --- |
| `lib\save\` 全目录 | `tomenet.acc` 账号、角色文件、`server` 世界状态、任务状态等 |
| `lib\data\` 全目录 | 日志、记录和生成的数据 |
| `lib\config\` 全目录 | 端口、管理员设置、控制台密码和封禁等配置 |
| `lib\game\`、`lib\scpt\`、`lib\modules\` | 当前运行版本的游戏数据、脚本和自定义模块 |
| 根目录 EXE、DLL 和 `BUILD-INFO.json` | 对应存档的准确运行版本 |

角色登录期间的内存状态必须通过正常停服保存，不能靠运行中的目录复制替代。

## 4. 迁移到另一台 Windows 64 位机器

1. 在旧机器执行正常停服，确认进程退出。
2. 复制**整个旧服务端目录**到新机器；或解压上一步制作的停服备份。
   不要用本次发布的“空白服务端包”覆盖旧机器的 `lib\save` 和 `lib\config`。
3. 在新机器按新路径建立游戏端口防火墙规则。若公网 IP 改变，更新路由器端口转发或域名。
4. 在新机器双击 `start-server.bat`。启动脚本使用所在目录，迁移后无需保持原盘符。
5. 客户端连接新 IP 或域名，检查原账号、角色、背包、房屋和世界状态。
6. 确认数据正常后保留旧目录作为离线回退备份。旧机器不要同时继续开服，避免出现两个分叉世界。

客户端也可整体复制到新电脑，包括 `TomeNET.ini` 和 `lib\user` 中的宏、窗口及偏好。
本包将 `DontMoveUser` 设为 `1`，配置保留在客户端目录，便于完整复制。
运行后更改服务器地址即可；角色和账号无需从客户端迁移。

迁移时先使用备份中的同一版本 EXE 和 DLL。升级是另外一步，应再次停服和备份，
仅替换发布说明允许替换的程序、DLL、游戏数据及脚本，保留既有存档和个人配置。
迁移或日常启动不要使用 `-r`、`-w`、`-f`、`-h` 参数，它们会重建世界、地图、物品外观或房屋。

## 5. 常见问题

- Staff 充能失败不会炸毁或减少数量；仍可能清空电量。吸收了 Staff 的 Mage Staff 也不会因充能失败失去该能力。
- Magic 弹药（魔法箭、弩矢和弹丸）不会被元素或爆炸伤害摧毁，包括背包、箭袋和地面上的物品。
  同时免疫电击消耗和祛魔降属性；已有存档中的 Magic 弹药自动生效，只需更新服务端。
- 大地图 Recall 不限距离：例如 `/recall 63 63`，地图的 X、Y 坐标范围均为 `0–63`。
  仍需先探索目的地；未探索的目的地按原规则回到最近一次访问的城镇。
  `/recall` 和召回道具共用这一规则，客户端无需更新。
- 随时洗点：按 `:` 打开聊天输入 `/respec`。普通玩家也可使用，任何地点、任意次数、免费，
  返还全部可分配技能点，保留种族和职业的初始技能；按 `G` 重新分配。
  旧角色按历史最高等级的正常点数兼容；更新后获得的 Skill／Learning 药水及升级额外奖励会记录并保留。
  只需更新服务端，客户端和配置无需更换。更新前正常停服并备份 `lib\save`，再替换服务端 EXE。

- DLL 缺失：确认完整解压，并检查杀毒软件是否隔离了文件；无需另装 MSYS2。
- 无法连接：先测试同机 `127.0.0.1`，再核对服务端是否运行、IP、TCP 端口、防火墙和端口转发。
- 新 IP 上看不到原角色：检查是否误启动了空白安装包，以及迁移后的 `lib\save\tomenet.acc` 和角色文件是否存在。
- 没有声音：此包保留音频能力，但音乐/音效素材以仓库内资源为准。
- 无法长期在线：检查 Windows 睡眠设置、重启和机器网络；启动脚本没有自动守护或重启功能。
