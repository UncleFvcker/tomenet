# 真神器携带、共享收藏页与神器显示计划

状态：已实现；Windows 服务端、客户端构建及专项回归通过，旧存档升级和重启检查通过。
基线：`merge/everlasting-skill`，`089b084`。

## 已确认的目标

- 胜利者可以正常获取、携带和装备真神器。
- 在现有 `P → v` Vault 内增加独立的 `True Artifacts` 页面。
- 用户已确认：收藏页沿用现有 Vault 的全服共享规则。
- 页面列出全部有效的玩家真神器；已储存的名称明亮，未储存的名称灰暗。
- 增强真神器、随机神器的名称和地面标识辨识度；用户进一步指定：参考攻击 Unique 时伤害数字的闪烁方式，真神器金色闪烁，随机神器紫色闪烁。

## 本计划采用的交互规则

1. 收藏页储存实物，允许取回。亮色表示当前库存中存在该神器，取出最后一件后恢复灰色，不另存永久点亮记录。
2. `P → v` 仍打开普通共享仓库；仓库内新增 `A` 键切换普通库存与 `True Artifacts` 页面，使用原有翻页、存入、取出和查看操作。
3. 收藏页显示 `Stored X / Total Y`，按稳定的神器编号排列，使用现有文本终端布局。
4. 普通库存不再混列真神器。存入真神器时自动进入收藏库存，其他物品仍进入普通库存。随机神器不进入真神器收藏页。
5. 真神器名称使用金色系闪烁，随机神器使用紫色系闪烁；收藏目录已储存的真神器也金色闪烁，缺失项固定灰色、不闪烁，并配合 `[Stored]` / `[Missing]` 文字，避免只靠颜色判断。
6. 收藏页内暂停自动到期计时，取回后继续原有剩余时间；重复存取不能重置或增加剩余寿命。收藏之外的到期规则不变。
7. 继续仅允许在大地图地表打开 Vault，不增加地牢内存取功能。

“全部”以服务端当前启用的真神器定义为准，不硬编码总数。普通玩家目录排除空记录、禁用条目和管理员专用神器；包含 Grond、魔苟斯皇冠等可获得的特殊真神器。转换前后不同形态按实际物品显示，不凭空生成另一形态。

## 实施顺序

### 1. 解除胜利者持有和获取限制

- 将默认配置和服务器缺省值中的 `KINGS_ETIQUETTE`、`FALLENKINGS_ETIQUETTE` 设为 false。两者一起关闭，覆盖已经称王又失去王位的角色。
- 发布说明明确要求已有服务器仅修改这两个配置项，不覆盖管理员整份配置；已有的 true 值会覆盖程序缺省值。
- 检查并验证普通拾取、自动拾取、给予/投掷转交、商店购买、仓库取回、装备、换层、Recall、重连及击杀掉落。
- 若发现未受这两个开关控制的同类阻拦，只修正实际遗漏。保留角色模式隔离、物品等级要求、Solo/Iron Team 规则，以及王者专用装备的准入规则。

### 2. 增加独立收藏库存和目录页

- 在 `store.c` 复用现有带 tag 的远程房屋机制，为真神器收藏创建独立库存；普通 Vault 的容量不被收藏品占用。
- 沿用房屋及物品存档读写。亮灭状态由收藏库存内的真实物品推导，不额外保存一份容易失步的收集位图。
- 旧存档中若普通共享 Vault 已有真神器，首次打开时安全迁入收藏库存，保留完整物品数据，普通物品不移动。先验证目的库存，再转移来源。
- 服务端生成有效神器目录、名称及当前库存状态；客户端不自己维护神器名单。目录空项只作显示，不能被取出、出售或变成物品。
- 客户端 `c-store.c` 增加页面切换、亮暗行、库存计数和分页。优先复用现有商店命令与 16 位索引；补齐服务端/客户端对页面身份、目录条目和操作的共同约定。
- 查看已存神器时使用现有物品查看流程；缺失项只显示目录名称，不展示虚构的实物属性。
- 收集同一编号的多件合法物品时保留实物和数量，不能把 Grond/皇冠等允许重复的真神器合并成一条布尔记录后丢失物品。

### 3. 接好存取、唯一性和到期规则

- 收藏库存只接收真正的真神器。服务端验证当前仓库会话、条目、数量、来源和取出资格，不能只相信客户端显示的颜色或位置。
- 收藏存入绕过该库存的“入屋销毁”规则；普通房屋和其他物品处理不变。失败时物品必须留在原处，不先扣除再销毁。
- 保留物品本身的所有属性、符文、铭文、鉴定状态、归属与原有交易规则。收藏页共享不等于绕过物品模式或等级限制。
- 收藏中的真神器继续占用全服唯一名额，不调用“销毁/重新可生成”的登记流程。合法多实例神器继续按原规则处理。
- 到期处理器根据真实收藏库存判断是否暂停；取回后恢复消耗当前剩余寿命，服务器重启后结果一致。
- 存取后更新所有正在浏览该共享收藏的客户端。两人同时取同一件时只能一人成功，服务端按当前实物重新校验，不能因库存重排取错物品。
- 管理员明确删除或世界重置仍走原有管理流程，不把收藏库存变成管理员无法维护的隐藏区域。

### 4. 增强神器名称与地面显示

- 复用 Unique 伤害数字的客户端动画颜色框架，添加两种独立的神器动态配色：真神器在亮金黄与浅金之间闪动，随机神器保持紫色主调并短暂闪出亮色高光；不采用黑色阶段，保证名字一直可读。不更改原有电系、法术或伤害数字配色。
- 补齐共享颜色定义、颜色字符与属性映射、客户端动态色解析和静态映射；沿用现有动画刷新节奏，不通过服务器持续重发物品或反复完整刷新界面制造闪烁。
- 在背包、装备、容器、仓库、商店、查看和拾取提示等相关入口应用一致的神器动态配色；名称列表加入简短的 `[TA]` / `[RA]` 标识，保证单色模式也能辨别。非交互的纯文本导出不包含动画控制字符。
- 验证仓库、背包等界面静止不操作时仍会闪烁；若原动画刷新只覆盖地图和消息区域，直接补上现有界面的刷新路径，不新建计时器或动画系统。
- 尊重已有 `no_flicker` 设置：关闭动画时，真神器固定亮金色，随机神器固定紫色；收藏缺失项始终灰色。
- 展示层增加颜色和标识，不改物品的真实名称、铭文内容或保存数据，不影响现有名称匹配和自动铭文规则。
- 不可用物品原有的灰色及 `!U` 等显示偏好仍有效，神器身份可由文字标识区分。
- 地面保留原来的武器、护甲、戒指等字符/图块形状，分别使用与名字一致的真神器金色闪烁、随机神器紫色闪烁；不统一替换成会丢失类别信息的星号。
- 同格堆叠时优先显示其中已经可见的真神器，其次随机神器。不得显示未被角色发现的物品；怪物覆盖、幻觉和陷阱查看优先级保持合理。
- 修正水体着色对神器高亮的覆盖；验证 ASCII 与图形客户端，若图块无法通过现有颜色表达则使用最小的客户端高亮处理，不另做整套素材。
- 未鉴定的可见神器允许凸显稀有度，但不提前透露真名、属性或完整鉴定结果。

## 验证与交付

1. **胜利者回归**：普通角色、现任胜利者、失去王位角色分别测试获取、装备、转交、换层、Recall、保存重载；确认不因王者身份销毁神器，掉落规则没有残留阻拦。
2. **收藏存取**：空库灰色、存入亮色、取出恢复灰色；随机神器拒绝进入收藏页；满背包、失败存入、重复请求、两名玩家争取一件均不丢失、不复制、不取错。
3. **完整性**：覆盖整份有效神器目录及超过 255 的位置；测试 Grond/皇冠多实例、转换形态、已有 Vault 真神器迁移、属性/符文/铭文不变。
4. **持久化与时间**：真实旧存档加载、正常停服、重启和跨机器迁移后库存及唯一性一致；收藏期间计时不减，取回后恢复，重复存取不刷新寿命。
5. **显示**：真神器金色闪烁/随机神器紫色闪烁/普通物品对照，背包、装备、容器、仓库、商店、查看与地面；不操作时动画持续，缺失目录项不闪；同格堆叠、水中、未鉴定、不可用灰色、幻觉、单色、`no_flicker` 和不同窗口高度。原 Unique 伤害、法术和地图动画不受新配色影响。
6. **构建与运行**：补充最小行为回归，运行相关现有检查，编译 Windows 64 位服务端和客户端；使用隔离存档及端口验收真实 `P → v` 操作。
7. **交付**：按既有要求只打包客户端和服务端替换文件，并附两个配置项的修改说明；不附带、更不覆盖玩家存档。完整功能需要同时更新服务端和客户端。

预计涉及：`lib/config/tomenet.cfg`、`src/server/variable.c`、`store.c`、`dungeon.c`、`object1.c`、`cave.c`、必要的网络收发与共享声明、`src/common/defines.h`、`common.c`、`src/client/c-store.c`、`z-term.c`、必要的现有动画刷新入口、相关测试及部署说明。优先沿用存档格式，协议变动按实际需要做最小调整，并显式处理版本差异。

## 实施与验证记录

- 新增 `artifact_vault` 传统房屋库存，沿用 4.9.26 存档格式；普通 Vault 与收藏分开计量容量，目录与亮暗状态直接根据实物生成。
- 页面复用商店包及 16 位条目索引，以神器编号作为稳定目录位置；`A` 切页请求和服务端会话验证已接通。
- 默认关闭两项胜利者礼仪规则，并修正商人物品邮寄中一处未受开关控制的胜利者阻拦。已有服务器仍须修改旧配置中的两个 true 值。
- 新增金色、紫色专用动态配色，客户端沿用现有终端闪烁刷新；`no_flicker` 映射为固定色，未储存目录项保持灰色。
- 服务端行为回归在启用/禁用 `ENABLE_INSTANT_RES` 两种构建下均通过；覆盖超过 255 的目录位置、多人存取、满背包与非法数量拒绝、旧库存迁入、符文属性保留、原生物品/房屋存档读写、到期暂停与恢复、管理员定位删除和合法多实例神器。
- 地面回归使用真实 `map_info()`，验证只突出可见神器、堆叠优先级、水体不覆盖高亮，以及旧客户端固定色。
- 客户端回归使用真实 `cmd_party()`、仓库按键处理、商店包解析和终端渲染，验证 `P → v`、`A`、16 位目录位置、界面静止时持续闪烁、缺失项不闪及关闭闪烁选项。
- 自动铭文、拾取/销毁和数量规则匹配时去除新加的显示标记，保留原始物品名匹配及铭文位置；原生客户端回归验证名称开头的正则规则和 `!G` 数量规则继续生效。动态颜色代码避开铭文命令字符。
- Windows 64 位服务端和客户端构建通过。隔离环境移除 MSYS2 的 PATH 后，旧 4.9.25 世界保存、新版加载并保存为 4.9.26、新版再次启动均通过；实际 Windows 客户端启动并到达新版服务端，测试进程均已结束。
- 未对用户正在运行的服务器和存档做任何修改；未逐一人工检查所有自定义字体、配色和图块组合。

收藏占用全服真神器名额，因此某件神器在公共收藏库存中时，其他地方不会再次掉落同一件唯一神器。发布仅提供替换文件和配置说明，不覆盖服务器配置及存档。
